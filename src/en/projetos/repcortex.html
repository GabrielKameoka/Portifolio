RepCortex.

A review arrives. Context matters.

A review platform with tenant organization, moderation rules, and sentiment analysis based on a lexicon adapted for Portuguese.

The problem

A platform that receives reviews needs to organize comments by client and support moderation decisions. Sentiment classification can help, but it does not replace the context of each comment.

RepCortex brings these concerns together in an API and Angular dashboard.

My contribution

In this personal project, I built review creation and moderation flows, dashboard integration, and rules for sentiment analysis in Portuguese.

The work covers domain modeling, authentication, tenant context, and persistence with Entity Framework Core and PostgreSQL.

How it works

  1. Identify the context. The API uses authentication and tenant information to handle each client’s reviews.
  2. Classify on creation. The service analyzes a comment before persisting the review. The classification is converted to a sentiment enum.
  3. Moderate. Operations allow approval, rejection, or response, with a check of the review’s tenant.
  4. Apply the response rule. Responding to a pending review also approves it, as defined by the entity rule.

Engineering decisions

Lexical analysis without generative AI

The implementation is based on VADER and adapted for Portuguese. It scores words and applies rules for negation, intensity, and contrast. It neither generates text nor relies on an external language model to classify comments.

The benefit is a local, explainable approach. The tradeoff is its dependence on vocabulary and rules, with limitations around irony and ambiguous context.

Rules close to the domain

The review entity owns moderation transitions, including approving a pending comment when it receives a response. This makes the rule explicit and testable apart from the interface.

Tenant context

The project uses EF Core filters and tenant checks in moderation operations. Isolation depends on valid context in every operation; filters alone do not prove all security scenarios.

What to inspect in the code

The repository lets you inspect the review service, domain entity, and sentiment analyzer. Existing tests cover domain rules and examples of lexical analysis.

As you explore, look at the order of classification and persistence, the approval rule when responding, and the analyzer’s negation tests. 

dotnet test

Current limits

Classification happens during creation. This case study does not describe it as background processing.

There is an authenticated SignalR hub with tenant groups, but event publishing in the review flow was not identified in the review. End-to-end realtime updates remain to be validated.

I do not claim accuracy percentages, guaranteed complete isolation, or production availability without specific measurements and tests. Lexical analysis is also not equivalent to human understanding of a comment.

What this project taught me

Choosing a simpler technique is also an engineering decision. A lexical classifier makes it possible to inspect the rules, understand outcomes, and discuss limitations.

Another lesson is to distinguish structure from behavior: configuring a hub or filter is not enough to prove the complete flow. Validation must follow the request through to the expected result.
